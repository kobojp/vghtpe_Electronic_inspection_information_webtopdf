# React 桌面改版驗證紀錄

驗證日期：2026-10-09。

## 已通過

- Python 3.13.3：68 項核心／API／PDF／報表管理／拖曳測試。
- 包含實際 wkhtmltopdf 轉換，驗證輸出 PDF 可搜尋且內容正確。
- 包含月底日期、失敗殘檔、取消競態、檔案鎖定、同名 PDF 與簽核頁回歸測試。
- Vitest：12 項前端月份、路徑及拖曳清單合併測試。
- TypeScript 嚴格型別檢查與 Vite 正式建置。
- Playwright：三組完整流程（報表新增／跨類型修改／刪除確認／重新載入／版本衝突，下載／跨頁進度／取消／PDF 擷取／設定保存，以及 PDF 拖曳提示／多檔加入／過濾／重複檔案／擷取），無前端例外。
- PyInstaller：Windows EXE 建置成功。
- 打包 EXE 的 headless 啟動驗證：成功啟動 API、讀取 378 份報表目錄並提供打包後的前端資源。
- Python 與打包設定共 21 個檔案語法檢查、Pipenv 鎖定一致性與 Git diff 檢查。

## 報表管理資料保護

- 對隔離的 data.json 執行新增、修改、刪除，確認重啟後可讀回。
- 保存前備份上一版完整內容；保留大樓清單、其他根欄位及單筆額外欄位。
- 拒絕無效名稱、網址參數、同大類重名及舊版本資料。
- 模擬備份與正式檔案替換失敗，確認原資料不變且暫存檔清理。
- 下載中的任務使用原快照，清單更新後清除勾選但保留月份。
- 瀏覽器測試使用臨時目錄資料，每個案例重設，未修改專案原始 data.json。

## PDF 拖曳驗證

- 原生事件資料轉換：完整路徑、多份 PDF、重複路徑、非 PDF、損壞／遺失檔案與資料夾。
- 桌面事件訂閱與 JSON 通知：測試以假的視窗物件驗證，不冒充原生 WebView2 實測。
- Playwright：拖入提示、路徑通知後加入、重複拖入與選檔合併、實際擷取兩份 PDF、忙碌／隱藏頁面拒絕加入及防止檔案導覽。原生路徑通知以 CustomEvent 模擬。
- 檔案總管 → WebView2 的實際拖入需一般 Windows 桌面驗證。

## 尚待驗證

本次執行環境的 WebView2 桌面視窗未完成初始化，連不含 API 或 React 的最小 HTML 測試也未載入。
一般視窗與隱藏視窗均已測試，補齊驗證程序缺少的 Windows 環境變數後結果相同。
因此不能宣稱原生桌面啟動或原生檔案對話框已通過。啟動器已加入載入逾時、錯誤日誌與失敗提示，避免視窗無限停留。

測試版須在一般 Windows 使用者桌面完成以下確認後，再視為正式可發布版本：

1. 雙擊 EXE，確認 WebView2 可載入四個頁面。
2. 使用原生對話框多選 PDF、選擇資料夾，確認路徑正確。
3. 從檔案總管拖入多份 PDF，確認不同資料夾的同名 PDF 均保留、重複檔案略過，並可完成擷取。
4. 實際下載一份報表，檢查內容與月份；網站內容與可用性未由本次測試驗證。
5. 關閉視窗時，確認目前任務與本機服務結束。

操作與開發指令見 README.md。可用 `--headless --smoke-test` 重現打包資源驗證；`--smoke-test` 驗證 WebView2 隱藏視窗載入。
